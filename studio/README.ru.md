# AI Фото — установка на сервер

Фоторедактор в браузере (открывает и сохраняет файлы Photoshop .psd) со встроенным помощником на вашей
локальной модели и файлами на вашем сервере.

Photoshop — товарный знак Adobe. AI Фото не связано с Adobe и работает с файлами в её форматах.

На сервере нужны только **nginx + PHP + Ollama** — то, что у вас уже есть. Ничего компилировать не нужно.
Редактор полностью автономный: всё загружается из его папки, интернет и сторонние сайты не нужны.

## Установка (5 минут)

1. **Скачайте готовую сборку.** GitHub → репозиторий `photocraft` → справа **Releases** →
   верхняя «Сборка N — дата» (с пометкой Latest) → файл `ai-photoshop-build-N-ГГГГ-ММ-ДД.zip`.
   У каждой сборки свой номер и описание «что нового» (то же — в `studio/CHANGES.ru.md`).
   Какая сборка стоит у вас, видно в шапке панели помощника: «Модель: … · сборка N».
2. **Распакуйте** — внутри одна папка `ai-photoshop`.
3. **Положите её на сервер** рядом с остальными приложениями: `/app/src/ai-photoshop/`.
   Папку можно назвать как угодно и переименовать потом — все пути внутри относительные.
   Помощник сам найдёт ваш `auth.php` на два уровня выше (`/app/src/auth.php`)
   и через него — `config.php`, `.env`, адрес Ollama и модель.
4. **nginx** — две обязательные настройки для помощника (готовый пример: `nginx.conf.example`;
   правила в нём не зависят от имени папки, старый блок `location /photocraft/` можно удалить):
   - `client_max_body_size 20m;` — помощник отправляет снимок экрана;
   - `fastcgi_read_timeout 200s;` — модель может думать дольше минуты;
   - для «Моих файлов» — блок `location ~ /api/files\.php$` с `client_max_body_size 1g;`
     (большие PSD) из того же примера.

   После правки: `nginx -t && nginx -s reload` (или перезапуск контейнера nginx).
5. **Папка для файлов пользователей создаётся сама**: `storage/ai-photoshop` рядом с корнем сайта
   (`/app/storage/ai-photoshop` при корне `/app/src`). Проверка: `https://ваш-домен/ai-photoshop/api/files.php`
   → `{"ok":true,…}`.
6. **Откройте** `https://ваш-домен/ai-photoshop/` — войдите в систему, если ещё не вошли.
   Справа появится панель «Помощник».

Обновление — то же самое: скачать новый zip и заменить папку. Свой `studio/config.js`
перед заменой лучше сохранить.

## Что внутри папки

| Путь | Что это |
|---|---|
| `index.html` | Страница редактора |
| `app/` | Сам редактор (WebAssembly, сжат и разрезан на части) и загрузчик |
| `studio/loader.js` | Показывает ход загрузки и, если что-то не так, какой файл не пришёл и почему |
| `studio/` | Панель помощника: `studio.js`, `studio.css`, `ru-labels.json` |
| `studio/config.js` | **Настройки панели** — можно править прямо на сервере |
| `api/assistant.php` | Помощник: проверяет вход, отправляет запрос в Ollama |
| `api/files.php` | «Мои файлы»: документы каждого пользователя на сервере |
| `api/settings.php`, `api/tools.php` | Внутренние настройки и список действий помощника |

## Настройки в `.env` (необязательно)

По умолчанию помощник берёт всё из вашей системы. Переопределить можно так:

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `AI_PHOTOSHOP_MODEL` | Модель помощника (нужны картинки и tools) | `GLOBAL_MODEL` |
| `AI_PHOTOSHOP_OLLAMA_URL` | Адрес Ollama или шлюза | `OLLAMA_IP:OLLAMA_PORT` |
| `AI_PHOTOSHOP_CONTEXT` | Размер контекста | `GLOBAL_MODEL_CONTEXT` или 32768 |
| `AI_PHOTOSHOP_TIMEOUT` | Сколько секунд ждать модель | 180 |
| `AI_PHOTOSHOP_MAX_TOKENS` | Длина ответа | 2048 |
| `AI_PHOTOSHOP_AUTH_FILE` | Путь к `auth.php`, если папка лежит не в `/app/src/` | ищется автоматически |
| `AI_PHOTOSHOP_ALLOW_ANON` | `1` — без входа (только для проверки!) | выключено |
| `AI_PHOTOSHOP_DATA_DIR` | Где хранить файлы пользователей | `storage/ai-photoshop` рядом с корнем сайта |

### Откуда помощник берёт модель

Главный источник — файл **.env** вашей системы. Помощник находит его сам: рядом с папкой приложения
и выше по папкам (обычно это `.env` в корне сайта или уровнем выше). Если .env лежит в другом месте,
укажите путь в переменной `AI_ENV_FILE`. Значения из .env важнее переменных окружения процесса:
если сервер запущен со старыми переменными, а .env поменяли, работает то, что написано в .env.

Порядок поиска (берётся первое найденное):

| Что | Где ищется |
|---|---|
| Адрес сервера модели | `AI_PHOTOSHOP_LLM_URL` → `LLM_URL`, `OLLAMA_URL`, `OLLAMA_HOST`, `OPENAI_BASE_URL` → `OLLAMA_IP` + `OLLAMA_PORT` → `$url_ollama` из config.php системы → `127.0.0.1:11434` |
| Модель | `AI_PHOTOSHOP_MODEL` → `GLOBAL_MODEL`, `LLM_MODEL`, `OLLAMA_MODEL`, `CHAT_MODEL`, `DEFAULT_MODEL` → `$global_model` из config.php → первая модель, которую отдаёт сам сервер |
| Размер контекста | `AI_PHOTOSHOP_CONTEXT` → `GLOBAL_MODEL_CONTEXT`, `LLM_CONTEXT`, `OLLAMA_CTXSIZE` → `$ollama_ctxsize` → 32768 |
| Ключ (если шлюз его требует) | `AI_PHOTOSHOP_API_KEY` → `LLM_API_KEY`, `OPENAI_API_KEY` |
| Протокол | `AI_PHOTOSHOP_LLM_API` или `LLM_API` = `ollama` / `openai`; без них определяется сам |

- **Любой сервер:** работает и с Ollama, и с OpenAI-совместимыми серверами (vLLM, GLM, LM Studio и
  другие). Адрес с `/v1` на конце считается OpenAI-совместимым. Если у адреса нет `/api/chat`
  (как у Ollama), помощник сам пробует `/v1/chat/completions`.
- **Любая модель:** имя модели сверяется со списком моделей сервера. Если такой модели там нет,
  берётся подходящая из списка. Если шлюз принимает имена-псевдонимы, которых нет в его списке
  (например `chat`), поставьте `LLM_MODEL_CHECK=0`.
- Если сервер не умеет вызывать инструменты, помощник сам переходит на текстовый протокол вызовов.
- **Как проверить:** наведите мышь на строку «Модель: …» в шапке панели помощника. Там написано,
  какая модель используется и из какой строки .env она взята. То же показывает адрес
  `api/assistant.php` в браузере.


Переменные со старыми именами `PHOTOCRAFT_…` тоже работают.

Запросы помечаются для шлюза как `ai-photoshop` через ваш `enrichLLMPayload()`.

## Как работает помощник

- **Совет** — объясняет, где найти функцию и что выставить. Ничего не меняет.
- **Сделай** — сам выполняет команды редактора: находит нужную команду, открывает диалог,
  выставляет значения, нажимает OK, смотрит на результат.
  Каждое действие видно в ленте, у каждого есть кнопка «Отменить»; всё отменяется и Ctrl+Z.
  Удаление, слияние слоёв, закрытие и сохранение — только после вашего «Разрешить».
- **Подсказки к фото.** Открыли снимок — помощник смотрит на него и на точные цифры тонов
  (`document.toneStats`: яркость, провалы теней, пересветы, контраст, насыщенность, цветовой сдвиг)
  и предлагает 2–3 правки одной кнопкой, лучше корректирующими слоями. Вручную — «Подсказки к этому
  фото» в пустой панели. Выключить автоподсказки: `suggestOnOpen: false` в `studio/config.js`.
- **Запомнить как действие.** После работы помощника (или применённой подсказки) под ответом есть
  кнопка «Запомнить как действие»: шаги сохраняются экшеном (Окно › Экшены) с теми же параметрами,
  и его можно применить ко всем открытым документам. Можно и словами: «запомни это как „Фото для
  каталога“», «сделай так же со всеми открытыми».
- **Быстрая строка — Ctrl+Shift+Пробел** (или кнопка-молния в шапке панели): поле внизу над холстом,
  ответ всплывает над ним, вся история — в панели. (Ctrl+Пробел занят: это временная лупа.)
- **Домик** справа в верхней строке редактора — на уровень вверх (`homeUrl` в `studio/config.js`).
- **Глаз** рядом с полем ввода — показывать ли помощнику экран (снимок уходит только на ваш сервер).
- Кнопка солнца/луны переключает светлую и тёмную неоморфные темы — и панели, и редактора.
  Остальные темы доступны в редакторе: Окно › Тема.
- **Фирменная тема** — стекло на градиентном фоне: Окно › Тема › Тёмная тема › Фирменная
  (или Настройки › Интерфейс). Панель помощника переключается вместе с редактором; выбор
  запоминается. Вернуться к неоморфным — кнопкой солнца в панели.

## Мои файлы

- **Ctrl+S** (и «Файл › Сохранить») сохраняет документ в «Мои файлы» на сервере — значок папки в
  шапке панели помощника. Первый раз спросит имя, дальше сохраняет туда же. «Сохранить как…» —
  под новым именем. В окне с именем есть и кнопка «На компьютер» — скачать вместо сервера.
- На сервер уходят документы: PSD, PSB, `.pcraft`, ORA, KRA. Экспорт (PNG, JPEG, TIFF, WebP…)
  по-прежнему скачивается на компьютер.
- **Мои файлы**: список с датой и размером, поиск, открыть, переименовать, удалить (файл уходит в
  корзину `.trash` в папке пользователя), «Новый документ», «С компьютера…» (открыть файл с
  компьютера; на сервер он попадёт после Ctrl+S), «На компьютер» (скачать открытый документ).
- У каждого пользователя своя папка (`storage/ai-photoshop/u-<пользователь>`), имена файлов на диске
  случайные, список — в `index.json`. Документ считается сохранённым, только когда сервер его принял.
- Если сохранить на сервер не удалось (нет связи, не вошли, файл больше лимита), файл сразу
  скачивается на компьютер, а копия остаётся в браузере: при следующем запуске панель предложит её
  открыть. Выключить «Мои файлы» — `files: ''` в `studio/config.js`.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Редактор не запускается | Под полосой загрузки написано, какой файл не пришёл и почему. Чаще всего: папка скопирована не целиком, или правило сервера отдаёт вместо файлов другую страницу |
| После заливки по FTP — старая версия или «Не удалось скачать app/loader…» | Программа заливки пропустила файлы «того же размера» (так умеет FileZilla). С этой сборки размер таких файлов меняется в каждой сборке, но надёжнее в FileZilla выбрать для существующих файлов «Перезаписать», а не «Перезаписать, если размер отличается» |
| В панели «Нужно войти в систему» | Вход в вашу систему в этом же браузере и на этом же домене |
| «Не найден auth.php системы» | Задайте `AI_PHOTOSHOP_AUTH_FILE` в `.env` |
| «Сервер помощника ответил не JSON» | PHP не обрабатывает `api/assistant.php` — проверьте блок PHP в nginx |
| Ошибка 413 | `client_max_body_size 20m` (пункт 4); при сохранении в «Мои файлы» — `client_max_body_size 1g` в блоке `api/files.php` и `post_max_size`/`upload_max_filesize` в PHP |
| «Не удалось создать папку для файлов» | Создайте `storage/ai-photoshop` и дайте PHP право записи, или задайте `AI_PHOTOSHOP_DATA_DIR` |
| Ошибка 504 / ответ обрывается | `fastcgi_read_timeout 200s` (пункт 4) |
| «Failed to fetch» / «Сервер оборвал соединение» | Начиная со сборки с номером, сервер помощника не молчит во время раздумий модели. Если всё равно обрывается — посмотрите `error.log` nginx в момент запроса |
| «Модель не умеет вызывать инструменты» | `AI_PHOTOSHOP_MODEL` с поддержкой tools |
| «Модель не принимает картинки» | Выключите «глаз» или укажите мультимодальную модель |

Проверка помощника без панели: откройте `https://ваш-домен/ai-photoshop/api/assistant.php` —
должно показать `{"ok":true,"model":"…"}`.

## Для разработчика

- Сборку делает GitHub Actions (`.github/workflows/studio.yml`) на каждое изменение ветки `main`.
- Мост редактора: `apps/photocraft-web/src/control_bridge.rs` — `window.__photocraftNative.call(метод, json)`,
  те же методы, что в `docs/control-protocol.md`. В консоли браузера: `await photocraft.call('ui.inspect')`.
- Темы: `NeuLight` / `NeuDark` в `crates/ui-egui/src/theme.rs`, отрисовка — `widgets::surface`,
  `widgets::neu_raised_shape`, `widgets::neu_pressed`.
- Панель: `studio/web/`, сервер помощника: `studio/api/`.
- Сохранение на сервер: `Services::write` (`apps/photocraft-web/src/web.rs`) → событие
  `photocraft:save` {name, token, saveAs, bytes} → `api/files.php` → `__photocraftNative.savedToServer(token)`
  отмечает документ сохранённым (`apps/photocraft-web/src/server_saves.rs`). Открыть файл со страницы:
  `__photocraftNative.open(имя, Uint8Array)`.
